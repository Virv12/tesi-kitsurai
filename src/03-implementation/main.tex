\subsection{\texttt{get} and \texttt{set} operations}
\label{subsec:get-set}

To read or write a key, the following steps are performed:
\begin{enumerate}
    \item The client connects to an arbitrary node of its choice, which acts as
    a \emph{router}.
    \item The client sends the key and, in case of a write, the value to be
    stored.
    \item The router computes the $N$ nodes responsible for that key
    (see Section~\ref{subsec:replication-ring}).
    \item The router sends the read or write request to the responsible nodes.
    \item The nodes respond with the requested value or confirm the write.
    \item The router aggregates the responses and returns as soon as it
    receives $R$ (for reads) or $W$ (for writes) successful
    replies.
\end{enumerate}

If fewer than $R$ (or $W$) nodes respond successfully, the
operation fails and an error is returned to the client.

\subsection{RPC}
\label{subsec:rpc}

Nodes communicate with each other using a custom RPC protocol over HTTP/2, it
was chosen for its multiplexing capabilities, allowing multiple simultaneous
requests over a single TCP connection, reducing latency and resource
consumption.
For efficiency, nodes maintain persistent connections with each other, reusing
them for multiple requests, we have observed that a single connection is not
able to saturate the machine's resources, so each node maintains up to 20
connections with each other node.

A request-response cycle consists of the following steps:
\begin{enumerate}
    \item The client serializes the request into a binary format.
    \item The client sends the request in the body of an HTTP/2 request.
    \item The server reads, deserializes and processes the request.
    \item The server serializes the response into a binary format.
    \item The server sends the response in the body of the HTTP/2 response.
    \item The client reads and deserializes the response.
\end{enumerate}

For serialization, we use the
\emph{postcard}\footnote{\url{https://github.com/jamesmunns/postcard}} library,
which provides a compact binary format with minimal overhead.
